# US-0175 — Memory Token Optimisation Design Spec

**Date:** 2026-05-10
**Status:** Approved
**Story:** US-0175 (EPIC-0026)
**Scope:** `tools/memory.js` + `tools/lib/memory-*.js`, `docs/memory/`, `MEMORY.md`, `CLAUDE.md`, Settings tab, CI workflow

---

## Overview

Reduce session-startup token cost by:

1. **Splitting** monolithic `MEMORY.md` (~10K tokens, 20 sections) into per-topic files under `docs/memory/{topics,sessions,snapshots}/`.
2. **Compacting** `MEMORY.md` to an auto-generated index (~500 tokens) listing topic file links.
3. **Archiving** stale topic files to `docs/memory/archive/<category>/` based on file mtime, with snapshot supersession (keep N=1 most recent per scope).

Topic files become the source of truth; `MEMORY.md` becomes a generated artefact regenerated by `generate-plan.js`.

## Filename Slugification Rule

Deterministic, implemented in `memory-classifier.js`:

1. **Extract date** from the title:
   - Match `(YYYY-MM-DD)` or `(... YYYY-MM-DD ...)` → use that date.
   - Else match `Session N` → look up session date from `progress.md` heading (`## Session N — YYYY-MM-DD`).
   - Else use file mtime at slug-generation time.
   - Topics get no date prefix.

2. **Extract slug body** from the title:
   - Strip parentheses content.
   - Strip em/en dashes (`—`, `–`) and convert hyphens within words to spaces.
   - Lowercase.
   - Replace runs of whitespace and non-alphanumeric chars with `-`.
   - Collapse repeated dashes.
   - Trim leading/trailing dashes.

3. **Truncate slug body** to 60 characters at a word boundary (do not split a word).

4. **Final filename:** `<date>-<slug>.md` for sessions/snapshots; `<slug>.md` for topics. `.md` is always lowercase.

**Examples (verified against current MEMORY.md):**

| Source title                                                                         | Filename                                                         |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| `Project Identity` (topic)                                                           | `project-identity.md`                                            |
| `Technology` (topic)                                                                 | `technology.md`                                                  |

## Category Detection (Auto-Classification)

Implemented in `memory-classifier.js`. Applied to every `## Heading` during migration.

1. **Snapshot:** title matches `/\(as of /i` → category `snapshots`.
2. **Session:** title matches `/\(Session \d+/i` or starts with `Session \d+` → category `sessions`.
3. **Lessons:** title is exactly `Lessons Learned` (case-insensitive) → special-cased; not split into a topic file (see Lessons Migration).
4. **Otherwise:** category `topics`.

---

## Snapshot Scope Detection

Used by archiver to decide which snapshots to retain.

**Rule:** scope = title text up to the first `(` (or full title if no parenthesis).

```
"Project Completion Status (as of 2026-05-05 Session 40)" → scope = "Project Completion Status"
"Project Completion Status (as of Session 38)"            → scope = "Project Completion Status"
"Coverage Status (as of 2026-04-15)"                       → scope = "Coverage Status"
```

Two snapshots share scope iff their scope strings (trimmed, case-insensitive) are equal.

**Archive rule:** group all snapshot files by scope; sort each group by date descending (date from filename); retain the first; archive the rest.

If a section is classified as snapshot but its title has no `(`, fall back to scope = full title and emit a soft warning to stderr.

## Staleness Logic

Implemented in `memory-archiver.js`.

**A topic is stale when** `now - mtime > config.memory.staleDays * 86400 * 1000`.

- Default `staleDays` = 90 (from `plan-visualizer.config.json` → `memory.staleDays`).
- Override via CLI flag: `--days N`.
- `topics/` and `sessions/` follow the staleDays rule.
- `snapshots/` follow snapshot supersession (above) regardless of age — older-than-most-recent always archives, even if < 90 days. The staleDays rule does not apply to snapshots.

**Archive operation:**

```bash
git mv docs/memory/<category>/<file>.md docs/memory/archive/<category>/<file>.md
```

`git mv` (not `cp + rm`) so `git log --follow` and `git blame` continue to work on archived files.

## CLI Interface

Single tool `tools/memory.js` with subcommands:

```bash
node tools/memory.js compact [--dry]
node tools/memory.js archive [--dry] [--days N]
node tools/memory.js migrate [--dry] [--force]
node tools/memory.js validate
```

| Command    | Behaviour                                                                                                                                                                                                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `compact`  | Read all files in `docs/memory/{topics,sessions,snapshots}/`, regenerate `MEMORY.md` as the compact index. Idempotent. `--dry` prints proposed `MEMORY.md` to stdout without writing.                                                                                                                                                                               |
| `archive`  | Apply staleness rule to topic files. Move stale files via `git mv` to `docs/memory/archive/<category>/`. Apply snapshot supersession independently of `staleDays`. `--dry` prints proposed moves. `--days N` overrides config.                                                                                                                                      |
| `migrate`  | One-time bootstrap: parse current `MEMORY.md`, split into topic files, archive superseded snapshots, triage Lessons Learned, rewrite `MEMORY.md` as compact index. Idempotent no-op if `docs/memory/topics/` already exists. `--force` overrides idempotency check. `--dry` prints all proposed file operations and the post-migration `MEMORY.md` without writing. |
| `validate` | Check that `MEMORY.md` matches `docs/memory/*` content. Exit 0 if matches, exit 1 with diff on drift. CI uses this to block PRs that desync.                                                                                                                                                                                                                        |

**npm scripts (added to package.json by `migrate-config.js`):**

```json
"memory:compact":    "node tools/memory.js compact",
"memory:archive":    "node tools/memory.js archive",
"memory:archive:dry":"node tools/memory.js archive --dry",
"memory:migrate":    "node tools/memory.js migrate",
"memory:validate":   "node tools/memory.js validate"
```

## Migration: Lessons Learned

Special handling during `migrate`. The `## Lessons Learned` section in current MEMORY.md is parsed entry-by-entry; each entry is reconciled with `docs/LESSONS.md`.

**Per-entry algorithm:**

1. Parse entry. Look for an `L-XXXX` identifier (regex `/L-\d{4,}/`).
2. **Has L-XXXX, ID exists in `docs/LESSONS.md`:** drop the entry from MEMORY.md (canonical version wins; no merge).
3. **Has L-XXXX, ID does not exist in `docs/LESSONS.md`:** append entry verbatim to `docs/LESSONS.md` with a `<!-- migrated from MEMORY.md 2026-05-10 -->` comment.
4. **No L-XXXX (free-form note):** allocate next available L-XXXX from `docs/ID_REGISTRY.md`, append to `docs/LESSONS.md` with the new ID and a migration comment.

After processing all entries, the `## Lessons Learned` section is removed from MEMORY.md (it does not become a topic file). The `docs/ID_REGISTRY.md` "Lesson" counter is updated if any new IDs were allocated.

No human review gate — fully automated. Risk: small duplicate if an MEMORY.md entry semantically overlaps a LESSONS.md entry but has a different L-ID. Acceptable trade-off; LESSONS.md remains the canonical source going forward.

## mtime Preservation (Migration)

For each section being split into a new topic file, set the new file's mtime to the timestamp of the last commit that modified that section in `MEMORY.md`.

**Implementation:** scan `git log --reverse -p -- MEMORY.md`. For each commit, parse the diff and record which `## Heading` lines were added or modified. Build a map `section_title → last_commit_timestamp`. After writing new files, run `touch -t YYYYMMDDHHMM <file>` to set mtime.

Pseudocode:

```js
const commits = exec(`git log --reverse --format=%H %ct -p -- MEMORY.md`);
const sectionTimestamps = {};
for (const commit of commits) {
  for (const line of commit.diff) {
    const m = line.match(/^[+-]## (.+)$/);
    if (m) sectionTimestamps[m[1]] = commit.timestamp;
  }
}
// After splitting, for each new file: touch -t with sectionTimestamps[title]
```

The implementation must handle:

- Section title renames (treat each title as independent; the last-edited timestamp of the current title applies).
- Sections that were added in a single commit (timestamp = that commit's time).
- Sections present in the very first commit of MEMORY.md (timestamp = first-commit time).

If git history is unavailable (shallow clone, missing data), fall back to current time and emit a warning.

## generate-plan.js Integration

After `loadConfig()` and before any data computation:

```js
const { compactMemory } = require('./lib/memory-index');
try {
  compactMemory({ root: ROOT });
} catch (e) {
  console.warn('[generate-plan] memory:compact skipped:', e.message);
}
```

`compactMemory` is a no-op when `docs/memory/` does not exist (fresh installs without migration). Wrapped in try/catch so a memory-system failure cannot block dashboard generation.

When `config.memory.autoArchive === true`, also call `archiveStaleMemory({ root: ROOT, days: config.memory.staleDays })` after compact. Default is `false`; archive is opt-in.

## Roll-Out Plan

Two PRs to minimise review burden and reduce roll-out risk:

**PR A: Tooling + tests + CI step.**

- New: `tools/memory.js` and `tools/lib/memory-{parser,classifier,archiver,index,validator,migrator}.js`.
- New: 7 test files in `tests/unit/`.
- Modified: `tools/migrate-config.js` to add `memory` block to existing configs.
- Modified: `.github/workflows/plan-visualizer.yml` to add validate step.
- Modified: `tools/generate-plan.js` to call `compactMemory` (no-op until PR B).
- Modified: `package.json` to add `memory:*` npm scripts.

PR A lands inert: there is no `docs/memory/` directory yet, so `compact`, `archive`, `validate` are all no-ops. CI passes because validate sees no memory files and no MEMORY.md sections to compare against.

**PR B: Migration commit.**

- Run `node tools/memory.js migrate --dry` and verify output matches expectations.
- Run `node tools/memory.js migrate` to perform the split.
- Commit the resulting tree:
  - 12 new files in `docs/memory/topics/`
  - 3 new files in `docs/memory/sessions/`
  - 1 new file in `docs/memory/snapshots/`
  - 3 archived files in `docs/memory/archive/snapshots/`
  - Rewritten `MEMORY.md` (compact index, ~500 tokens)
  - Updated `docs/LESSONS.md` if any orphan lessons migrated
  - Updated `docs/ID_REGISTRY.md` if new L-XXXX IDs allocated
- Modified: `CLAUDE.md` (Mandatory Session Startup + Session Close Checklist updates).

PR B is reviewable as a mechanical transform — large diff, but each file is a verbatim section extraction.

If PR B is reverted (rare), `MEMORY.md` reverts to monolithic and topic files vanish. PR A remains landed and inert. No half-migrated state is possible.

## Error Handling

| Failure                                                                        | Behaviour                                                                             |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `compact` invoked, `docs/memory/` missing                                      | No-op, exit 0 (treated as "memory layout not yet bootstrapped").                      |
| `migrate` invoked, `docs/memory/topics/` exists and is non-empty, no `--force` | Exit 0 with message "memory layout already bootstrapped; pass --force to re-migrate". |
| `migrate --force` invoked, existing topic files                                | Overwrite all topic files; warn user via stderr.                                      |
| `archive` invoked, `docs/memory/` missing                                      | No-op, exit 0.                                                                        |
| `validate` invoked, drift detected                                             | Exit 1 with unified diff to stderr.                                                   |
| `git mv` fails (e.g. file already exists at destination)                       | Exit 1 with the underlying git error.                                                 |
| `git log` query fails for mtime preservation                                   | Use `now` as fallback, emit warning to stderr.                                        |
| Fallback snapshot scope detection (no `(` in title)                            | Use full title as scope, emit warning to stderr.                                      |

## Out of Scope

- Token-usage measurement / reporting — not needed; the index size reduction is verifiable by inspection.
- Memory file linting (e.g. enforcing front-matter, validating dates). Future story.
- Cross-project memory sharing or sync. Out of scope.
- Manual unarchive — users run `git mv` themselves to recover an archived file.
- Topic-file content schema or validation (e.g. requiring "Last Updated" field). Out of scope.
